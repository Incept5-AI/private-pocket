# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A private, cloud-free companion app for the **Pocket (PKT01)** voice recorder, open source as `incept5-ai/private-pocket`. Layout:

- **`ble/`** — the BLE protocol (`PROTOCOL.md`, the source of truth) and Python/bleak tools used to verify it from the Mac. `captures/` (gitignored) holds PacketLogger captures of the official app plus captured live-stream MP3s.
- **`ios/PrivatePocket/`** — the SwiftUI iPhone app, which is where nearly all the work happens. Its `README.md` lists the features.
- **`docs/`, `plugins/`** (gitignored, local only) — clones of Pocket's own upstream repos (a Mintlify docs starter and their AI/MCP plugins). Use them for reference only; nothing here builds or uses them.
- `recordings/` (gitignored, mode 700) — real recordings. Personal data: never share.
- `report/` (gitignored) — private notes about Pocket, not for the repo.

## Commands

```bash
# iOS: regenerate project, build unsigned, sign, install and launch on the iPhone
cd ios/PrivatePocket && ./sign-install.sh          # reads signing.env; DEVICE=<udid> overrides

# Compile-check only (no phone needed)
cd ios/PrivatePocket && xcodegen generate -q && \
  xcodebuild -project PrivatePocket.xcodeproj -scheme PrivatePocket \
  -destination 'generic/platform=iOS' -derivedDataPath build CODE_SIGNING_ALLOWED=NO build -quiet

# BLE from the Mac (the phone app must be disconnected: the Pocket talks to one central at a time)
cd ble && set -a && . ./.env && set +a && uv run pocket.py BAT FW SPACE 'LIST_DIRS'
uv run pocket.py --wait 10 --out x.mp3 STA STO      # --out saves audio received on …a1
```

**Reading the app's log from the Mac:** the protocol log is written to `Documents/pocket-log.txt` (`DiskLog`; also shareable from Pocket details). Pull it with `xcrun devicectl device copy from --device <udid> --domain-type appDataContainer --domain-identifier com.incept5.private-pocket --source Documents/pocket-log.txt --destination pocket-log.txt`. It is the quickest way to see what the Pocket answered.

There are no tests and no linter. To exercise app logic without the phone, copy the relevant `App/*.swift` files into a scratch directory with a `main.swift` and run it with `swiftc`, feeding it a TTS MP3 at 16 kHz/32 kbps mono (`ffmpeg … -ar 16000 -ac 1 -b:a 32k`). Background noise transcribes as nothing, so it is useless as test input. Thread logic compiles on the Mac without the app: `Intelligence.swift` up to `// MARK: - Reading a conversation`, `Library.swift` up to `final class Library`, `Place` from `Location.swift`, `Speakers.swift` up to `enum Diarizer`, `Threads.swift`, and `Digest`'s `stop`, `tokens`, `midNames`, `phrases`, `terms` and `reading` with `Findings.dayName`, plus stubs for `LLM`, `LLMConfig`, `LLMError`, `Brand`, `Planner`, `DeviceConfig` and `You` (`matches`); feed it sidecars pulled from the phone.

- **Adding a Swift file:** run `xcodegen generate` first. The `.xcodeproj` is generated from `project.yml` and gitignored.
- **Bundle id** is `com.incept5.private-pocket`; the Keychain service name is read from the bundle id.
- **App icon:** `App/Assets.xcassets/AppIcon.appiconset` (1024 px, opaque). The README logo is `assets/logo.png`.
- **Signing:** Xcode on this Mac has no Apple ID, so automatic signing fails. `sign-install.sh` signs by hand with the profile, identity, app-id prefix, team and phone from the gitignored `signing.env` (template: `signing.env.example`). Don't switch the project to manual signing: that fails with "profile is Xcode managed".

## Secrets

`ble/.env` (mode 600, template `ble/.env.example`) optionally holds `POCKET_SK`, a device session key (the app pairs on its own; the Mac tools need one), plus device and server defaults and `SERVER_KEY`. Server values stay blank by default (examples only in `.env.example`). Never print the keys.

- The pre-build `gen-defaults.sh` bakes them into the gitignored `Generated/DefaultDevice.swift` (`DefaultDevice`, `DefaultServer`).
- On first launch `AppModel.init` copies `SERVER_KEY` into the Keychain, once, guarded by the `seededServerKey` flag.
- At runtime all secrets live in the Keychain: `llm.key`, `stt.key` (which falls back to `llm.key`), and per-device session keys.

## Protocol essentials (details in `ble/PROTOCOL.md`)

- **Service `001120a0-…`:**
  - `…a2`: commands, ASCII `APP&…`
  - `…a3`: replies and events, `MCU&…`
  - `…a1`: raw MP3 (MPEG-2 L3, 16 kHz mono, 32 kbps, about 4,000 B/s)
- **Recovery:** when the Pocket will not take a key, or keeps dropping the link, the way back is: Bluetooth off on the phone (Settings), reset the card (side button three times, then hold until the light blinks red), Bluetooth on, hold the button five seconds until it blinks blue, pair. The walkthrough's last page and the pairing panel both spell this out.
- **Session key:** `APP&SK&<key>` must be sent first, or the device silently ignores every command. In pairing mode (side button held 5 s, light blinking blue) the device accepts any 16-character key and adds it to the ones it holds (earlier keys stay valid). Outside pairing mode a wrong key drops the connection at once. Without any key the link still delivers `MCU&STA`/`MCU&STO` events and the live stream, which is how an unpaired device works in the app. `PocketLink.handshake` sends the stored key; only a real refusal (the drop, or a reply that is not `MCU&SK&OK`) sets `keyRejected`, a timeout does not. Keyless or refused, the link carries on for events and audio and `tryPairing` runs: once per connection after a device-initiated drop (`pairAttemptPending`), and from `AppModel.keepPairing` every 15 s in the foreground for two minutes, then every minute, never while recording. It sends the stored key first unless refused in the last 45 s, else a fresh key, which pairing mode accepts; outside pairing mode a wrong key just costs a reconnect. `pair` (the Pair now button) goes straight to a fresh key.
- **Live streaming needs no command.** While recording, live MP3 arrives on `…a1` unprompted, whether started by `APP&STA` or the button. Downloads (`APP&U&…`) arrive on the same characteristic, so `PocketLink` routes `…a1` bytes to the download in progress if there is one, otherwise to `onLiveAudio`.
- **Deleting:** there is no delete over BLE. Deletion is only via USB mass storage: `APP&USB&1`, re-plug, delete under `RECORD/<date>/`, unplug. While the cable is in, the device reports 0 space and ignores `LIST`.
- File names are UTC timestamps (`yyyyMMddHHmmss`). With the side switch on call (contact mic, the card on the back of the phone) they are `PH` + `yyMMddHHmmss`, the start event says `MCU&REC&CALL`, and `LIST_DIRS`/`LIST` do not list them, so only the live stream captures them. `APP&REC&SECEN` reads the switch (`MCU&REC&CON`/`CALL`); it is `DeviceStatus.mode`, shown on the card, and saved per recording as `RecordingMeta.mode`. `PocketTime.parse` handles both; `DeviceStatus.recordingName` carries the name from `MCU&STA&` to the stop.

## iOS architecture

App sources are in `App/`. `Shared/` is compiled into both the app and the `PrivatePocketWidgets` extension (`Widgets/`), which hosts the Live Activity and the Control Center toggle: `RecordingAttributes`, `StartRecordingIntent`, `StopRecordingIntent` and `ToggleRecordingIntent` (all `LiveActivityIntent`, performed in the app through a static `handler`; that kind is what makes Control Center run them in the app rather than the extension) plus `PocketLook`, `LightDot`, `PocketFacts`, `LevelBars` (loudness as bars, drawn by the recording takeover and the Live Activity) and `SharedState`. The signing profile is a wildcard without App Groups, so anything the extension needs from the app travels in the activity's state or through `SharedState`, a Keychain item in the app's access group (`<team prefix>.com.incept5.private-pocket`, which `Widgets/PrivatePocketWidgets.entitlements` and `sign-install.sh` grant the extension); `PocketLink.status` writes the recording flag there and calls `ControlCenter.shared.reloadAllControls()`. `Shared/Brand.swift` is the palette (concept D: graphite ground, cyan for anything you can tap, amber for recording, blue for work, pink for life); the app is dark-only (`UIUserInterfaceStyle` Dark in `project.yml`, `.preferredColorScheme(.dark)` and `.tint(Brand.act)` on the root view), every `List` and `Form` hides its system background for `Brand.ground`, and recording is always `Brand.record`, never `.orange`. Keep app-only types out of `Shared/`. `App/LiveActivity.swift` (`RecordingActivity`) runs the activity from `AppModel`: iOS only lets an app *start* one in the foreground, so `refreshPresence` starts it while connected (light and battery, `Prefs.islandPresence`), and recording, saved and waiting are updates, which work from the background. While it records, `AppModel.startActivity` sends every two seconds the words, the last seven and a half seconds of loudness as thirty bars (`LiveLevels.bars`, `ContentState.levels`), what Record was pressed into (`context`), what the reader has caught (`caught`) and a quiet thread named in the room (`recall`); `Widgets/PrivatePocketWidgets.swift` draws a five-bar waveform and the timer when compact, three bars when minimal, and when expanded the card with its light (`IslandCard`), the phase (`IslandHeadline`), the timer (`IslandFigure`) and `IslandBottom` (the waveform, the words, a chip and Stop; the read sentence once saved; Record via `StartRecordingIntent` when idle); the Lock Screen (`LockScreenView`) turns amber while recording; `App/Intents.swift` has `StartRecordingIntent` and the App Shortcuts. `sign-install.sh` signs the `.appex` with its own entitlements before the app.

- **`PocketLink`** is the CoreBluetooth central. It handles scan, connect, the command/reply exchange, downloads and status, and exposes the hooks `onLiveAudio`, `onRecordingStarted`, `onRecordingStopped(name, heard)` and `onLinkLost`. Rules it keeps, each learned from a failure:
  - **One command at a time.** `send` waits its turn (`takeTurn`) and `exchange` does the work; two commands in flight took each other's replies and both timed out. `download` holds the channel for the whole file, a recording starting (`startRecording`, or `MCU&STA&` arriving) stops it with `PocketError.interrupted`, and it returns a `FetchedFile` whose `whole` is false when fewer bytes came than `MCU&U&` announced.
  - **Cancels are not losses.** iOS answers every `cancelPeripheralConnection` with a `didDisconnect`. `cancelConnection` cancels only a connected or connecting peripheral and marks it (`cancelling`), `didDisconnect` ignores a marked one, and a real loss tears down with `teardown(cancel: false)`. Cancelling inside the disconnect handler made a loop of about forty a second in the background that kept the Pocket from ever reconnecting.
  - **Attempts are numbered.** `teardown` bumps `attempt`; `establish` waits with its number (`waitUntil(attempt:)`), stops with `superseded` once it changes, and never tears down what replaced it. A cancelled wait disconnects only if it is still the current attempt. A failed background wait is re-armed after 5 s.
  - **A recording survives a reconnect.** The keyless handshake keeps `recordingSince`, `recordingName` and `mode`; `tryPairing` never runs while audio has streamed in the last 5 s (`lastLiveAudioAt`). `watchForStaleRecording` runs after each reconnect during a recording: 20 s with no audio (and, when paired, a listing that is not growing) means it was stopped while the phone was away, and `onRecordingStopped(name, false)` finishes it.
- **`AppModel`** is the orchestrator:
  - A keep-alive loop (`setActive`) reconnects every 15 s while the app is in the foreground. In the background it instead arms `PocketLink.standby`: a pending `connect` on the known peripheral that iOS completes whenever the Pocket advertises (phase `.waiting`), with the handshake run from the delegate (`checkStandbyReady`). The central has a restore identifier, so iOS relaunches the app for Bluetooth events; `willRestoreState` hands the peripheral back and `attach` treats an already-connected one as connected. Both are skipped when the user disconnected or during Add-device discovery. An unpaired device (no key, or `link.keyRejected`; see `AppModel.canCommand`) is still connected so button-started recordings stream; the record button and sync are hidden until it is paired.
  - Sync, plus transcription and diarisation, which run concurrently. `autoSync` runs a quiet sync after every connection (foreground loop, standby `onConnected`, pairing) when the device is paired, `syncsAutomatically` is on (per-device `autoSync`, optional, default true) and nothing is recording.
  - Summary and Ask.
  - At a stop, `wrapUp` takes what the recording gathered at once (the reader's catches into `liveCarry`, its stream detached into `stoppedStreams`), so a new recording can start meanwhile; `saveStopped` runs the save once per name (`saving`, which the takeover shows as Saving…), then `endActivity` (a no-op if a newer recording has the island) and `fetchSoonIfMissing` (a sync 20 s and 2 min later if the save failed). A new `MCU&STA&` while a stream is still open finishes the old one first. `toggleRecording` is guarded by `toggling` and says a failed start or stop in `aiError`.
  - `completeRecording` decides whether to keep the streamed copy: kept only if the stream had no gap and its duration is within ±2 s of the device's `LIST` seconds; otherwise the file is downloaded. The listing is tried three times (a call recording, `PH…`, never appears in it); when it or the fetch fails, the stream is kept and marked `RecordingMeta.partial`, as is anything kept after an inferred stop or from a short fetch. A sync fetches the Pocket's file for a partial copy once a session (`recheckedPartial`) and replaces it through `Library.replaceAudio` when that holds more. Unpaired: whatever streamed is kept, since nothing can be listed or downloaded.
  - Sync runs one at a time (`syncing`), stops at a recording, skips what was deleted here, never saves an empty file, and queues transcriptions one after another (`enqueueTranscription`).
- **`LiveSession` (`Live.swift`)** handles the live stream:
  - It writes the stream to `Caches/Live/` (a write that fails marks a gap rather than crashing). `bytes` is not published; `seconds` is, once a second.
  - `detach(name:)` takes a stopped recording's stream out at once as an `Ending` (its file, transcriber and gap), which `finish()` completes on its own; a transcriber still finishing never writes over the next session's words. The server's transcriber gives a slice 60 s, pauses after three failures, and `finish` waits no more than 20 s; a phone recogniser that cannot start is abandoned and keeps at most about a minute of audio while starting.
  - `MP3Packetizer` (AudioFileStream) splits it into frames, always, whatever the live transcript is doing; `MP3Decoder` decodes each batch once into float PCM, which feeds `LiveLevels` (ten levels a second, the root mean square of each tenth on a −50 to −12 dB scale, its own `ObservableObject` so only waveforms redraw, `stalled` after a second and a half without data; `LiveWave` in the recording takeover) and the phone's transcriber; the frames themselves feed the server's. The transcribers:
    - `LocalLiveTranscriber`: AVAudioConverter, then SpeechAnalyzer
    - `RemoteLiveTranscriber`: 15 s chunks sent to Whisper, with word times offset by chunk start
  - Every 45 s it re-diarises the whole file so far.
- **`Library`** handles storage: `Documents/Recordings/<device id>/<yyyy-MM-dd>/<UTC>.mp3` plus a `.json` sidecar (`RecordingMeta`).
  - **A job that awaits writes through `Library.mutate(id) { meta in … }`**: the moment as it is now, only the fields that job owns, nothing if it was deleted meanwhile, no write if nothing changed. `update` is only for a copy taken just now; writing back a copy held across an await lost renames, ticks and names. A new reading goes through `AppModel.carryOver`, which keeps each re-read item's id, reminder, event, tick, Not mine and (once placed or added by hand, `NextItem.byHand`) wording, and keeps placed, ticked, dismissed and hand-added items the new reading missed. Placing is per item (`placeItem`, guarded by `placing`).
  - Deleted moments are remembered in `Recordings/deleted.json` (`wasDeleted`), so sync and USB import never fetch them back; clearing all moments remembers them too. A sidecar or `threads.json` that no longer decodes is copied aside as `.bad` before anything writes over it. `Recording.startedAt` is parsed once, in its init.
  - **Every field added to `RecordingMeta` must be optional**, or existing sidecars stop decoding. The same goes for `ThreadRecord`, `ThreadState` and `PeopleBook` in `Recordings/threads.json`.
  - The same applies to `DeviceConfig` in `Devices.swift`, where a decode failure wipes the saved devices.
- **`Prefs` (`Devices.swift`)** wraps UserDefaults. Views use `@AppStorage` with the same key names so labels refresh.
- **Speech to text and the language model are each local or remote, chosen independently** (`Prefs.sttRemote`, `Prefs.llmRemote`):
  - Local STT: `Transcriber` in `OnDeviceAI.swift`, on SpeechAnalyzer/SpeechTranscriber (iOS 26+). Only a few locales can be reserved, so `reserve` evicts ones that aren't favourites.
  - Remote STT: `RemoteSTT` in `LLM.swift`, OpenAI `/audio/transcriptions` with `verbose_json` and word timestamps.
  - Local LLM: FoundationModels, with about 6k characters per chunk.
  - Remote LLM: OpenAI `/chat/completions`, with `chat_template_kwargs.enable_thinking=false` and any `<think>` block stripped from the reply.
  - Summaries and Ask map-reduce long transcripts in chunks of `LLMConfig.chunkChars`.
  - `Languages.auto` works only with remote STT: local transcription throws `autoNeedsServer`.
- **Speakers (`Speakers.swift`)**:
  - `Diarizer` posts the whole audio file to `/v1/audio/diarize`. Speaker ids hold only within one request, so the app never diarises chunks.
  - `Speakers.align` rules: midpoint rule, narrowest overlapping segment wins, nearest segment within 1.5 s, a gap of 2 s starts a new turn, speakers renumbered by first turn.
  - The output format is `[MM:SS] Speaker N: text`. Keep it stable.
  - `Recording.transcriptForModel` feeds that speaker text to the LLM whenever there are 2 or more speakers.
  - **Your voice.** `You` (`Brief.swift`) is who the user is: `Prefs.yourName` from Settings (what people call you after commas), else `Prefs.calendarName`, which `You.learn` takes from the participant EventKit marks `isCurrentUser` (on every foreground sweep, and before a reading when still unknown). `Speakers.levels` and `wearer` find the voice at least 6 dB louder than every other, the wearer's (never on a call or a sample), and log the levels as `voices …` in the protocol log so the margin can be checked against real moments. The reader is told both (`You.hint`; `CalendarEventRef.others` is the invitees without you) and gives the words behind every speaker name; `Analyst.checkedSpeakers` then drops a name the label says itself (unless introducing itself: "I'm Ravi", "Ravi here"), any name but yours on the wearer, a name on two labels, and both names when two voices are named and neither is you. You are never one of the people (`PeopleNames.canonical`, `Analyst.isPerson`), and a promise you made is an action. `RecordingMeta.speakersNamedByHand` keeps the names you gave; a new reading replaces the last one's guesses (`AppModel.speakerNames`) and is given `Recording.transcriptForReading`, where those guesses are labels again (given as names, the reader took them as fact and named no one). Naming a speaker offers That's me. The protocol log says what became of each proposed name (`speakers …`, labels and reasons, never names) and the shape of the diariser's reply (`diarize reply: …`, keys and counts, to see whether it sends voice prints). `AppModel.analyse` reads a moment once at a time (`beingRead`, taken before its first await).
- **Naming clash:** the app's transcript type is `TimedTranscript` because FoundationModels already exports `Transcript`.

- **The screens (`Shared/Brand.swift`, one family of colour on ink):** `RootView` has four tabs with symbols and the iOS 26 search tab: Now (`NowView.swift`), Threads (`ThreadsView.swift`), People (`PeopleView.swift`), You (`YouView.swift`) and Ask (`AskView.swift`, the search tab). There is no record bar. While the Pocket records, `RecordingTakeover` (`Takeover.swift`) is the whole screen, an overlay on `RootView` raised by `AppModel.takeover` when a recording starts (from the app or the card's button) or the app opens during one, revealed out of the Dynamic Island (`IslandReveal`): amber, `Breath` swelling with the loudness, the timer large, `LiveWave` large, the words, `ThreadHintBox`, the reader's catches with tick and cross, the card's answers, and Stop as a shutter; Hide (chevron) lowers it, the live block on Now raises it again, and after the stop it shows Saving, then Saved, and lowers itself. Record is `RecordButton`: an amber shutter beside Now's greeting and in the top bar of `ThreadView`, `PersonView` and `MomentView`, where it records into them. The Pocket's state is `PocketPill` above Now's greeting, which opens `PocketView` (the card with its real light, pairing, today's list) as a sheet; Settings is the gear in Now's header and in You's. **Now** is the home and the tape: blocks for the hour (set up, needs pairing, Live with the reader's chips, tapped to raise the takeover, said to the card, the brief, just read, yesterday set with Listen back, six o'clock, needs you, noticed), then `Tape.swift`: every moment as a `TapeBand` in its kind's colour (cobalt work, coral life) with pins for what it left behind, grouped by day newest first, the `DateFinder` rail while scrolling, and `TapeScaleControl` for Day, Week (`TapeWeek`), Month (`TapeMonth`) and Year (`TapeYear`, with on this day a year ago); - **The brief, the reader in the room, the card, listen back (`Brief.swift`, `Replay.swift`):** `Briefs.upcoming` matches calendar events in the next hours (`Planner.events`; full Calendar access is asked for once, on Now, `Prefs.askedBriefs`) to people in the readings and builds a `Brief` (their open promises, what you owe them, the last figure, the last moment); Now shows it as a teal block that opens `BriefView`, and `Briefs.schedule` (on the launch sweep) sets a time-sensitive notification ten minutes before each. While it records, `AppModel.startLiveReader` runs `Analyst.liveRead` on the rolling transcript every 25 s (it needs the live transcript and a model); `liveItems` and `liveDecisions` show in Now's live block and in the recording takeover with `confirmLive` and `dismissLive`, and `liveCarry` takes what was ticked into the moment when `analyse` runs after the stop. `watchForCard` scans the live transcript for "Pocket, …": "remind me to" makes a reminder, anything else is `ask` over every transcript; the answer is a `CardAnswer` block on Now and a `Notify.now` notification. `Replay` plays the anchored brief and key lines of yesterday's moments eight seconds each, from the morning block.
- **Threads kept (`Threads.swift`):** `ThreadStore` (an environment object, `AppModel.threads`) keeps a `ThreadRecord` per thread in `Recordings/threads.json`, out of backups like the moments: its name (`named` once the user gives one), `aliases` (the lowercased phrases that find its moments), `pinned` and `excluded` moments, `doubted` (recorded into it but read as something else), `mergedInto`, `hidden` ("Not a thread"), `apart`, and its `ThreadState`. `discover` makes a record for each phrase that runs through two or more moments (`Digest.phrases`: a capital mid-sentence in a reading is a name; at a sentence's start or in a title a word counts only when the moment never writes it in lower case and the library writes it with a capital mid-sentence somewhere, `midNames`, or the name tagger knows it; people are left out word by word), and drops records nobody touched whose phrase no reading uses any more. `live` works out every `LiveThread` from the records and the library (phrases matched, plus pinned, minus excluded; two moments, or one for a thread the user named): `open` items with their age (`Ageing.lapse`: a month past their date, or three months with none; a promise said again by the same person is carried and marked renewed, matched on `promisedAct`), `isBack` (spoken in the last three days after thirty quiet), `weight`, `changes` (the reading's, plus lapses and ticks), `recall(before:)` and `plainStory`. `catchUp` reads a thread's unread moments against its state, four at a time, with `ThreadReader` (`ThreadDraft` on the phone, JSON on a server, from the readings, never transcripts; `plain` without a model) and is run one job at a time through `enqueue`: after every `AppModel.analyse` (`readThreads`), on the launch sweep for up to six live threads, and when a thread's page opens. Mending: `rename`, `merge`, `keepApart`, `hide`, `pin`, `exclude`, `keep`, `split`, `create`. The people book (`PeopleBook`: names that are one person, names that are not people) is kept in the same file and applied through `PeopleNames.canonical` in `Recording.people` and `Digest.people`.
- **The calendar event (`Brief.swift`):** when a moment is read and Calendar is allowed, `AppModel.analyse` finds the event it happened in (`Briefs.event(during:seconds:)`: of the events it overlaps, from a quarter of an hour before it starts, the one it overlaps most) and keeps it as `RecordingMeta.event` (`CalendarEventRef`: title, times, invitees without you, rooms, resources or anyone who declined; a bare address becomes a name), with `calendarChecked`. The reader is told the event and the invitees as the likely speakers, to be named only when the conversation shows which voice is whom (`CalendarEventRef.hint`), and `inferredSpeakers` lands as before. The launch sweep looks up moments from before Calendar was allowed, once, and reads again up to ten that had an event. Sample moments are never matched. `MomentEventLine` shows the event under a moment's header and opens Calendar there; naming a speaker offers the invitees as one-tap names. Every calendar read (`Planner.events`, so the briefs and `Briefs.event`) skips the calendars switched off in Settings → Calendars to read (`CalendarsView`, `Prefs.excludedCalendars`; a calendar added later is read until switched off); `CalendarEventRef.calendarID` and `isReadable` stop a switched-off calendar's event being shown or told to the reader, and `AppModel.calendarSwitchedOn` has moments that found no event look again on the next sweep.
- **Intelligence (`Intelligence.swift`):** `MomentInsight` lives in `RecordingMeta.insight`: kind, title, `brief` (two or three `Anchored` sentences addressed to the user), `next` (`NextItem`s: action, date or promise, with who, when, a resolved date, `reminderID`/`eventID`, done, dismissed), `keyLines`, people, `inferredSpeakers`, `decisions`, `questions` (asked and left open) and `figures` (money, quantities, counts, each with what it was for). `Analyst.analyse` reads a transcript with the configured language model, on the phone through `@Generable InsightDraft` or on the server as JSON, in chunks when long, merged over `Analyst.heuristic`; every sentence and item comes back with a verbatim quote that `Anchor.find` turns into a time in the audio by matching it against `RecordingMeta.words`. `AppModel.analyse` runs after every transcription (including live ones finished in `completeRecording`), applies inferred speaker names where the user gave none, then `placeNext`: actions into a Pocket list in Reminders with their due date, dates into Calendar, when `Prefs.autoReminders`/`autoCalendar` are on (default). `setDone` ticks a reminder too, `dismiss` removes it, `remindMe` makes a chase reminder for a promise, `refreshDone` reads completion back. The old `actions`/`promises`/`upcoming` arrays stay for sidecars written before; `items` folds them in.
- **Consent, notices and state words:** `NextItem.sure` is the reader's mark that an item was said plainly with enough detail to act on; `isSolid` is sure plus a quote. `placeNext` places only solid items, and only when `Prefs.autoReminders`/`autoCalendar` are on (default off). The first moment with a solid to-do shows `ConsentCard` in `TodoSection` (Always flips the setting and places; Not now sets `Prefs.askedReminders` and never asks again); `EventSection` does the same for Calendar with `askedCalendar`. `AppModel.editItem` changes an item's wording and renames its reminder (`Planner.renameReminder`). Every reminder and event the app makes carries `privatepocket://moment?id=<recording id>` in its URL field and its notes (`Planner.momentURL`; the scheme is `CFBundleURLTypes` in `project.yml`); `RootView.onOpenURL` switches to Now, which pushes the moment through `AppModel.openMomentID`. `AppModel.syncPlaced` is the two-way sync for a moment's placed items: `Planner.lookup` reads each back (title, due or start date, completion, location, length) and `take` copies what differs onto the `NextItem`; a reminder or event the user removed there clears the id and sets `unplaced`, which shows Add again and keeps `placeNext` from putting it back; `Planner.ensureLink` gives older items their link. `syncAllPlaced` runs it for every moment with something placed, on the launch sweep, when Insights appears, and a second after `EKEventStoreChanged` (`Planner.onChange`, subscribed in `setActive`). `Planner.warm` re-requests already-granted access so a fresh store has connected before any lookup. Errors never alert: `NoticeBar` at the top of `RootView` shows `model.aiError`, and the Pocket tab shows `link.lastError`, for eight seconds, in plain words with what happens next (`AppModel.placingFailed` for Reminders and Calendar refusals). `PocketView`'s `statusText` is five words, Ready, Recording (the timer stands in), Saving, Away, Needs pairing, with `detailText` beneath; the link's own phase is the Link row in `PocketDetails`. The hero compacts (`compactHero`) once today has moments and nothing is recording, and the stream and engine lines show only when they have something to say. Settings opens with Where things run (`privacyText`), which names where speech to text and reading run now and that backups leave the moments out; Export everything (`AppModel.exportAll`, an `NSFileCoordinator` zip of the Recordings folder) sits above Start over. The Recordings folder is excluded from backups (`isExcludedFromBackup` in `Library.root`). Read again (the old Redo) lives on the moment's Details page; Delete is in the moment's footer and asks first; sample verdicts show only in the Samples screen. `RecordingActivity.showRead` puts the kind and first sentence of the moment just shown as Saved into the Live Activity (`ContentState.read`) for half a minute, from `AppModel.analyse` when `lastSavedName` matches. Type uses text styles, never fixed sizes (the timer is a `@ScaledMetric`); `PocketIllustration` and the welcome nudge honour Reduce Motion; the waveform exposes a playback value and the date finder is hidden from VoiceOver; `Brand.dim` reads at 4.5:1 on the ground. Words: moment for the thing in the app, recording for the act and the files on the card.
- **Your own server (`Server.swift`):** `ServerStatus.shared` asks `<llmURL>/models` (4 s timeout) on foreground and before each job. With `Prefs.serverWhenReachable` on, `Prefs.sttRemoteNow` and `llmRemoteNow` fall back to the phone while it does not answer; every dispatch reads the `…Now` variants and only Settings reads the raw switches.

- **Sample moments (`Samples/`):** `manifest.json` holds eight short fictional conversations, one per kind, with the kind each is expected to be read as; `make.py` (run with `uv run --no-project python make.py`) speaks them with macOS voices and encodes them like the Pocket (16 kHz mono 32 kbps MP3) into `Samples/SampleMoments/`, which ships in the app bundle as a folder. `SampleMoments` reads the manifest; `AppModel.addSamples` saves them through `Library.save` dated over the last few hours (`RecordingMeta.sampleID`, `expectedKind`), then transcribes and reads each in turn, so they exercise the real path on the phone or the server. They are dated a day and a half apart over the last eleven days, so Insights has a previous week to compare with and promises that have had time to fall due. `SamplesView` (Settings → Try it) shows expected against read; `MomentCard` shows the same tick on the card. `RecordingMeta.labelKind` is the user's correction of a kind and wins over the reading (`Recording.kind`). The README's screens (`assets/screens/`, 600 px, rounded corners, 256 colours) are these samples on an iPhone 17 Pro simulator: a throwaway copy of the repo with a sanitised `ble/.env` (the example Pocket id, no server) and the deployment target lowered to the simulator's SDK, transcribed by a local Whisper server and read by a local OpenAI-compatible model, driven by screenshot-only hooks that were never committed. Real recordings never go in the README.

## Server defaults and gotchas

- **No hard-coded servers.** Defaults come from `ble/.env` via `gen-defaults.sh`, into the generated `DefaultServer` enum: `SERVER_URL`, models, `DIARIZE_URLS` and the key. If `SERVER_URL` is empty, `LLMConfig.hasDefault` is false: STT, the LLM and speakers default to off/on-device and the "Reset to …" buttons are hidden. Never put a real URL, hostname or key in Swift.
- **Testing a key:** many gateways serve `/models` without auth, so the STT test sends a real 1 s silent WAV instead. That same `/models` answer is where the model pickers come from: `ServerStatus.check` keeps the list (`ModelList.parse`), `ServerFields` fetches it for its own URL and key, and `ModelList.ordered` puts speech models first for speech to text. A server that lists nothing leaves a text field.
- **Whisper input:** whisper.cpp accepts mp3 and wav, but not m4a.
- **Diarisation contract:** `POST <base>/audio/diarize`, multipart `file` + `preset`, returning `{segments:[{start,end,speaker}]}`. Several base URLs are tried in order; 404/5xx/unreachable moves to the next.
- **Plain http:** `NSAllowsArbitraryLoads` is on so private-network `http://` servers work.

## Open-source hygiene

The repo root is a git repo published as `incept5-ai/private-pocket`. Before committing, check that nothing personal is staged: `.env`, `signing.env`, `ble/captures/` (the PacketLogger traces contain the session key), recordings and MP3s, and the `docs/`, `plugins/` and `report/` directories are all gitignored and must stay that way. Use example identifiers like `PKT01_GREY_2617abcd` in docs.
